# 128K Context on 6GB VRAM — Implementation Plan for Lynx

## Goal
Enable 128K context window for Qwen2.5-Coder-7B on RTX 4050 (6GB VRAM) using KV cache quantization + Flash Attention.

## Research Summary

**Qwen2.5-Coder-7B Architecture**: 28 layers, 4 KV heads (GQA), head_dim=128
- Much smaller KV cache than Llama-3.1-8B (32 layers, 8 KV heads)

**Key Technique**: llama.cpp KV cache quantization (`-ctk`, `-ctv`) + Flash Attention (`-fa`)

| KV Quant | 128K KV Size | Total VRAM (with 4.4GB model) | Status |
|----------|-------------|-------------------------------|--------|
| q4_0     | ~0.9 GB     | **~5.3 GB**                   | ✅ Fits, mainstream llama.cpp |
| q8_0     | ~1.8 GB     | ~6.2 GB                       | ⚠️ Tight |
| tq3_0    | ~0.8 GB     | ~5.2 GB                       | ✅ Best, needs custom llama.cpp build |

**Recommended**: `q4_0` KV cache — available in current llama.cpp, 75% KV reduction, minimal quality loss.

## Required Changes

### 1. Update `src/config.rs` — Add KV cache config fields
```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ModelCfg {
    // ... existing fields ...
    #[serde(default = "default_kv_type_k")]
    pub cache_type_k: String,  // "f16", "q8_0", "q4_0", "tq3_0"
    #[serde(default = "default_kv_type_v")]
    pub cache_type_v: String,
    #[serde(default)]
    pub flash_attn: bool,
}

fn default_kv_type_k() -> String { "q4_0".into() }
fn default_kv_type_v() -> String { "q4_0".into() }
```

### 2. Update `src/backend.rs` — Pass KV cache flags to llama-server
- In `LlamaServer::spawn()`, add:
  - `--cache-type-k <cfg.model.cache_type_k>`
  - `--cache-type-v <cfg.model.cache_type_v>`
  - `--flash-attn` if `cfg.model.flash_attn`

### 3. Update `lynx.toml` — New defaults for 128K
```toml
[model]
ctx_size = 131072      # 128K context
cache_type_k = "q4_0"  # Quantized K cache
cache_type_v = "q4_0"  # Quantized V cache (requires flash_attn)
flash_attn = true      # Enable Flash Attention
n_gpu_layers = 99      # Offload all layers
```

### 4. Update `src/main.rs` — Validate config combination
- Warn if `cache_type_v != "f16"` but `flash_attn = false`
- Warn if `ctx_size > 32768` without KV quantization

## Validation Steps

1. **Build**: `cargo build --release`
2. **Pull model** (if not present): `lynx pull`
3. **Test server startup**: `lynx serve` — should show KV cache init logs with quantized sizes
4. **Test 128K context**: `lynx --task "read a 100KB file and summarize it"`
5. **Monitor VRAM**: Use `nvidia-smi` during inference

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| q4_0 KV + FA instability on CUDA | Fallback to q8_0 if garbled output (known issue on Blackwell) |
| Quality degradation at 128K | Test with coding tasks; q4_0 KV has <1% perplexity increase per research |
| OOM on long prefill | Reduce `--batch-size` / `--ubatch-size` in `extra_args` |
| llama.cpp version mismatch | Pin llama.cpp version in install docs |

## Out of Scope

- TurboQuant (tq3_0) — requires custom llama.cpp build
- Multi-GPU / tensor split
- CPU offload (`--no-kv-offload`)

## Acceptance Criteria

- [ ] `lynx serve` starts with 128K ctx + q4_0 KV + FA on RTX 4050 6GB
- [ ] `nvidia-smi` shows < 5.8 GB VRAM used at idle
- [ ] Can process 100K+ token conversation without OOM
- [ ] Output quality comparable to 8K baseline on coding tasks
